# F1 Break Reminder — VS Code Extension Design

## Purpose

A local, personal-use VS Code extension that tracks how long you've been coding in the current
VS Code window and shows an F1-style flag status (green / yellow / red) in the Secondary Side
Bar, playing a sound cue on each color transition. Red means "take a break, touch some grass."

## Architecture

Single VS Code extension with two cooperating parts:

1. **Extension host timer** — tracks elapsed minutes since the window opened and compares
   against configurable thresholds.
2. **WebviewView in the Secondary Side Bar** — renders the animated flag, elapsed time, and
   plays the audio cue for the active zone. Communicates with the extension host via
   `postMessage`.

There is no OS-level floating/always-on-top window — VS Code extensions cannot create UI outside
the VS Code window. The Secondary Side Bar (right-hand panel) is the closest equivalent to an
"upper right" persistent widget.

## Components

- `src/extension.ts`
  - Activates on startup (`onStartupFinished`).
  - Sets `startTime = Date.now()` on activation.
  - Runs a `setInterval` every 10 seconds:
    - Computes `elapsedMinutes = (Date.now() - startTime) / 60000`.
    - Reads `breakReminder.yellowThresholdMinutes` and `breakReminder.redThresholdMinutes` from
      configuration.
    - Determines current zone: `green` (below yellow threshold), `yellow` (at/above yellow,
      below red), `red` (at/above red).
    - Posts `{ type: 'tick', color, elapsedMinutes }` to the webview every tick, and additionally
      relies on the webview to detect color changes for sound-triggering (see below).
  - Registers `FlagViewProvider` as a `WebviewViewProvider` for a new view in a new view
    container placed in the Secondary Side Bar.
  - Listens for `{ type: 'reset' }` messages from the webview: resets `startTime = Date.now()`.

- `src/flagViewProvider.ts`
  - Implements `resolveWebviewView`, sets `webview.options.enableScripts = true`.
  - Loads `media/webview.html`, injecting `asWebviewUri` paths for `webview.css`, `webview.js`,
    and the three audio files.
  - Forwards messages between extension host and webview.

- `media/webview.html` / `webview.css` / `webview.js`
  - Renders a waving-flag graphic via CSS animation; color controlled by a class
    (`flag-green` / `flag-yellow` / `flag-red`) applied to the container.
  - Displays elapsed time as `Hh Mm`.
  - Tracks the previously-seen color in the webview's local JS state; when an incoming `tick`
    message's color differs from the last-seen color, plays that color's `<audio>` element and
    updates the CSS class.
  - Click handler on the flag posts `{ type: 'reset' }` to the extension host, and immediately
    resets local state to green (optimistic update; confirmed by the next `tick`).
  - Each `<audio>` element has an `onerror` handler that no-ops (missing/corrupt sound file
    doesn't break the UI).

- `media/green.wav`, `media/yellow.wav`, `media/red.wav`
  - Synthesized tones generated by a one-off local script (not downloaded), committed to the
    repo:
    - Green: a short, soft single chime.
    - Yellow: a sharper double-beep.
    - Red: an alarm-style tone (longer, more urgent).
  - These are placeholders — swappable later with any user-supplied audio files of the same
    names, including real F1 clips the user has rights to use, without any code changes.

## Settings (`package.json` → `contributes.configuration`)

- `breakReminder.yellowThresholdMinutes` (number, default `60`)
- `breakReminder.redThresholdMinutes` (number, default `90`)

Both editable directly via VS Code Settings UI or `settings.json`.

## Data Flow

1. VS Code window opens → extension activates → `startTime` set → timer starts.
2. Every 10s: extension computes elapsed time + zone → posts `tick` to webview.
3. Webview updates elapsed-time label every tick; on zone change, swaps flag CSS class and plays
   the corresponding audio file once.
4. User clicks the flag in the side bar → webview posts `reset` → extension sets new
   `startTime`, and the next `tick` reflects `green` / `0m`.

## Edge Cases / Constraints

- Sound only plays while the webview is actually rendered (Secondary Side Bar panel open with
  this view visible). If the panel is closed/hidden, no audio plays until it's reopened — this
  is a VS Code webview limitation, not a bug. Noted in the README.
- No persistence across VS Code restarts — matches the "wall-clock since window opened" choice;
  reopening VS Code resets the clock naturally.
- Missing/corrupt audio files degrade gracefully (flag still updates visually; sound just
  doesn't play).

## Testing

Manual verification only (personal single-user extension, no CI):
- Temporarily lower thresholds to e.g. 0.1 / 0.2 minutes during development to confirm
  green→yellow→red transitions and sounds fire correctly.
- Confirm click-to-reset returns the flag to green and restarts the timer.
- Restore real thresholds (60 / 90) before daily use.
